## 从 pdoom 学到、用上了的
1. **每帧都是歌曲时间 t 的纯函数，导出时每帧取快门内 8 个子帧求平均** → 真运动模糊。
   抖动和颗粒按帧号取值，不跟连续的 t 走（pdoom 的 `frameIdx` 规矩），否则子帧之间会糊成一片灰。
2. **词按内容查**（`word('mine', 35)`），不写死时间。逐词卡拉 OK：提前 0.4 s 暗着出现，唱到哪亮到哪，从不抢在人声前面。
3. **每个镜头换一种「字长在哪」**：层 / 线 / 海平线 / 星星，不当字幕用。
4. **一根贯穿始终的母题**：pdoom 里那颗火花，到这里换成她的青色光点。
5. **一个颜色只属于一个时刻**：酸性黄绿只给 mine，橙只给睁眼那一下；品红是正在唱的词；其余都是靛紫加骨白。
6. **用字宽轴表达**（Archivo 62–125）：长音就把字拉宽。字体是从 pdoom 拷来的 Archivo 和 IBM Plex Mono（OFL 许可，在 `fonts/`）。
7. **冷面小注释**（mono）：`L03 · attn.2`、`d.0367 p = 1.000`、`boot ok · eyes: open`、`stars awake: 4 / ∞`。
8. **动作停住再猛冲**，硬切落在词头或强拍上，切点那一帧压一层亮。

## 和 v3 哪里不一样
- v3 已经借了 pdoom 的「白热→橙→冷却」和 outExpo 入场。我这版没再走这条路，换成了**运动模糊采样、按内容查词并逐词擦亮、母题线、颜色归属、字宽轴**这几样。
- v3 的字是叠在画面上的；这版的字长在画面里的物体上（层、线、海平线、星星）。
- 她是从上一个镜头那根线**聚**出来的，因果关系连着；v3 是切过去的。

## 没做到 / 没验证的
- ⚠️**没听过声音**。节奏是按 words.json 和 audio.json 对齐的：切点落在词头和强拍上，动作落在拍点上。实际手感要 Leo 来判断。
- ⚠️整段我只看了接触表和十几张带运动模糊的静帧，**没逐帧看完成片的运动**。成片我只确认了时长和帧数（见文末）。
- pdoom 的**按 32 px 分块自适应采样**没做，用的是固定 8 个子帧。泛光是 Canvas 模糊叠加，不是 WebGL 的 bloom。
- 她只有胸像（cybergirl.js 的范围）。分镜里「浮在海面上」「整片海从她身上亮开」，我只用胸像加海面亮圈近似了一下。
- 每行文字的字距没做逐字形的 kerning（pdoom 的 `layout()`），直接用的 Canvas 整串 fillText，所以字体自带的字距是保留的。
- 只看了接触表的缩略图：28–30 s 撞过去的大字有时和下一层的字叠在一起（LAYER 和 BY 交叠），我觉得算动感，但可能嫌乱。
- 已验证：mp4 465 帧 / 15.50 s，有音轨（28.3–43.8 s 原曲，服务器加了淡入淡出）；从成片抽了 36.2 s 的帧，聚合的运动模糊是在的。整段渲染 45 s。
- 出片用的是我自己起的 `serve.py --port 5431`（serve.py 是全局单状态，三个 Animator 同时用 5430 会串帧）。
