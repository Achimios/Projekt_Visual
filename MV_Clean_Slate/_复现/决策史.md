# Clean Slate · 决策史（为什么这么做，别走回头路）

> 只看结论会重复踩坑。每条写：当时的问题 → 选了什么 → 为什么 → 代价。

## 1. 代码动画为主，Seedance 放最后
**问题**：MV 要 189 s 的连续画面，人物要动、镜头要穿。
**决定**（👤2026-11-02 修正 DSH 初稿的「不用生成式视频」）：不是禁用，是顺序。先让 LLM 明确意图锚点，再做代码动画和 Seedream 低帧，**最后**局部或全画面丢给 Seedance。
**为什么**：时间轴要精确到词，代码能做到；生成视频放在锚点定了之后，改动才不用整段重来。
**代价**：人物大部分时候是低帧动画，「她真的在动」还没完全解决（👤：「长画面是女孩的时候，女孩是一定要用动作的」）。

## 2. 三个会话各做一支，不选一支
**问题**：全片怎么推进？
**决定**：三个会话（主 + Animator1 + Animator2）**各学一个参考仓库**，各交一支完整 MV。值钱的是**分歧点**。
**为什么**：一个人做会收敛到一个安全解；并行三支能拿到三种镜头语言，然后揉。
**代价**：三支都有明显短板，且互相不知道对方的长处——后来靠互评（`_反馈/` 里那两条短评）才交换。
**学到**：互评要在**同一轮**做，否则各自都做完了才发现"该借的没借"。

## 3. 参考仓库指定，不自由挑
| 谁 | 学哪个 | 学到什么 |
|---|---|---|
| Animator1 | `_外部仓库/pdoom-video`（MIT） | 每帧 = 歌曲时间的纯函数；卡拉OK式逐词排版；每帧取快门内 8 个子帧求平均 = 真运动模糊 |
| Animator2 | `_外部仓库/mg-styles-15`（#13 像素风 + #08 HUD） | 索引色 + LUT、CRT 开机序列、错帧描边、锁定框 |
| 主会话 | `openfilm-examples/one-prompt` 等 | 三维排版、bloom / halation、甩镜 |

**为什么指定**：自由挑会全都挑到"看起来最像的"，拿不到分歧。

## 4. headless Chrome 分段渲染
**问题**：连续 POST 约 1000 帧后浏览器卡死（内存）。
**决定**：`render_segments.sh`，每 20 s 一个新浏览器，逐段 ffprobe 验时长，卡住重试 3 次，最后 concat + 整首原声重铺。
**代价**：全片 ~6–14 分钟；段间是**硬切**（所以段长要小到看不出接缝，或让段落边界正好落在切点上）。

## 5. 九宫格：低帧动画，好用，但不是万灵药
**问题**：她要有动作，但没有逐帧图。
**决定**：Seedream flash 一张图出一组帧，切开当序列帧（一张停 2–3 帧）。flash 够用，复杂场景才偶尔用 pro（👤）。
**为什么**：同一张图里人物最一致，成本低（👤2026-11-02：工作得不错）。
**👤 2026-11-01 修正**：帧数按画面精度和当前需要定，不一定是 9。大特写 + 慢抬头要更多帧，远景 3 帧够。九宫格只是出图时的打包方式。
**已知限制**：等分格子不一定守得住（`breathe_a/b` 都乱了，要挑或重出）；分开生成的几张图拼动作，衣服细节会跳（Animator1），所以连续动作要放同一张图。
**接续**（👤提出，**未实测**）：下一组的参考图用上一组最后一格或整张九宫格，加角色原图。

## 6. 抠图用 BiRefNet，不用"从四边抠黑"
**问题**：她要贴在别的画面上，需要透明背景。
**踩坑**：为了省事用了"从图片四边往里抠黑色"→ 她脚下那团光是亮的，被当成她身体的一部分留下来了。
**决定**：全部改用 `4_Eidolon/tools/matte.py`（**BiRefNet**）。吃图也吃视频，输出透明 PNG 序列。
**为什么**：BiRefNet 判的是"人"这个语义对象，不会把发光点算进去。
**教训**：凡是"按颜色/亮度猜前景"的抠图，在自发光、辉光、逆光的画面上都会坏。

## 7. 词时间对齐到人声起音（`words_snap.json`）
**问题**：声画差 0.1–0.3 s，唱到词了画面还没动。
**排查**：整首歌**没有**整体偏移，是 Whisper 给个别词标早了/晚了。
**决定**：用**人声分轨里每个音的起点**重新对齐全部 440 个词 → `words_snap.json`。
**结果**：0101 落在 4.06 / 4.60 / 4.84 / 5.09 s，正好卡在八分音符拍点。
**教训**：先排除"全局偏移"再怀疑"逐词误差"，不然会一直在加常数偏移。

## 8. 素材是「插槽」，不是硬编码
**决定**：人物位置 = 一行路径列表，指向一组透明 PNG。
**为什么**：换更好的图 / 视频 / 3D 模型时，动画和镜头不用动。
**怎么换**：新图 → `matte.py` 抠 → 改那行路径。视频也能直接喂 `matte.py`。3D 就在 Blender / three.js 里按需要的角度渲一组 PNG。

## 9. 播放器不是通用编辑器，交互按通道分
**问题**：要不要在网页里查看、选中、拖动、修改元素？
**决定**（👤2026-11-02 修正 DSH 初稿的「不做对象编辑」；分工见 `4_Eidolon/_设计/从FK到IK.md` §3）：
| 数据 | 通道 | 落到播放器上 |
|---|---|---|
| 低频、高带宽（结构、镜头意图） | 语言交给 LLM | 打点写备注 |
| 中频的零碎参数 | 参数条 | 每个镜头现场生成一排滑块，用完就扔 |
| 高频、实时（缓动、手感） | 手柄 | 边播边调曲线，录下来 |
**不做的**只是通用的 AE 式编辑器：流程没固化时，UI 应该是一次性的。

## 10. Eidolon 的 Python 效果怎么进 MV
**决定**：分两类，不搞统一转换。
- 要实时跟歌 / 要反复迭代 → 转 JS（数据海、示波器、符号阵列、信息图）
- 重计算、离线出片 → Python 渲成帧序列/视频，当素材喂网页（四维切片、最优传输、粒子碎裂、面部瓦解）
**为什么**：符合「一个镜头只认一个真源工具」和「后台离线做素材 / 现场实时接管」的分层。
