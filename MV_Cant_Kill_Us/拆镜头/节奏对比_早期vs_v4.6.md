## 0. ⚠️ 先说一个 bug：13g 的画面从 47 s 起越来越早于音乐，到 56 s 后提前 0.58–0.71 s

**数据**
- `edl.py preview` 每段用 `-frames:v nf` 截帧，但**素材不够长时这一段就短几帧，后面不补**。我把剪辑表每一行的 ffmpeg 命令原样重跑（输出到 null）数帧：10 段各短 1–3 帧，合计 **17 帧 = 0.71 s**。
- 交叉校验（必须相等的量）：13g 实长 96.29 s，剪辑表写的是 97 s，差 0.71 s ✔；红色警报闪帧剪辑表在 89.92 s，视频里在 89.21–89.25 s ✔。
- 欠帧的主要是 3D 碎裂片段（`16_碎裂_3D_*`，51.52–56.32 s 连续 6 段共欠 11 帧）+ 32.42 / 47.50 / 75.00 / 80.87。
- 结果：剪辑表**本意**里 drop1 的 18 个切点有 15 个在拍上、11 个在重拍上；**实际渲染**出来只有 3 个在拍上、1 个在重拍上（详见第 2 节）。偏移 ≈ 1.5 拍，切点几乎都落在**半拍**上。

**判断**：这本身就足以让 drop1 和狂语「不对拍」。**下一轮评节奏前先修这个再重出**，否则看到的不是剪辑表的节奏。
修法建议（没改 Eidolon 的代码，留给主会话）：段内帧不够时用 `tpad=stop_mode=clone` 补到 nf 帧，或者数帧不等就报错；出片后断言「视频时长 = end」。

## 2. 数据说了什么（不加解释）

1. **切点密度的曲线形状不同。** 05：0.24 → 1.38 → 2.13 → 2.19 → 2.01 切/小节，一路加速后在 drop 保持。v4.6：0.37 → 0.31 → 0.50 → 1.13 → 1.25，drop 之前几乎不切，drop 里只有 05 的一半。
2. **05 的 drop1 镜头一半以上 ≤ 2 拍**（≤1 拍 12 个、1–2 拍 13 个）；v4.6 的 drop1 ≤1 拍只有 1 个，主体是 2 拍–2 小节。
3. **05 的切点抢拍。** 05 / v2 的切点集中在拍前 0.03–0.12 s（相位图里蓝柱都在 0 左边）；剪辑表本意的 v4.6 也在拍前 0–0.05 s；实际渲染的 v4.6 在 drop 后均匀散开、偏在拍后 0.05–0.2 s（= 上面那个 0.58–0.71 s 漂移折算到拍内）。
4. **v4.6 的回想 / build 是「镜头内运动」多，05 是「切」多。** v4.6 镜头内运动是 05 的 1.9×（回想）/ 3.5×（build），但运动里来自切点的只占 10–12%，05 是 55–75%。
5. **26–32 s（👤夸过的 Kuramoto macro 运镜）**：v2 每秒镜头内运动 4.8–6.7，v4.6 同段 5.5–7.2 —— 运镜的量 v4.6 没丢，差别在 v2 这一段有 29.1–29.9 s 一串闪帧和 32.3–32.8 s 的切。
6. **静止段：开头 05 比 v4.6 更静**（0–14.9 s、19.5–25.7 s、45.9–52.0 s 都是静止段），**drop 里 v4.6 更静**：57.4–61.7 s（4.3 s，四维插入「先快后缓」的尾巴 + 四维切片慢转）、67.2–70.8 s（tiger 插入尾巴 + 暗的原片）、92.75–96.3 s（3.5 s）。05 在 drop1 / 狂语最长静止 1.8 / 1.4 s，且每段都夹在两个运动尖峰之间。
7. **05 drop1 的结构**：剪辑表只有每 2 小节（3.2 s）一行原片 @1.25×，15 行全部检出（误差 −0.03…−0.09 s）；其余 ~20 个切点是**原片自身的切**，被 1.25× 压密后带进来的。
8. 运动和 threat 通道在**任何**版本里都不相关；heartbeat 弱相关（r ≤ 0.4）。

## 3. 我的解释（推断，没验证过感受）

- **「全局节奏」差主要是三件事叠加**，按影响大小排：
  ① 渲染漂移让 56 s 以后的切点整体落到半拍上（这是 bug，不是剪辑决定）；
  ② 早期版本的节奏来自**离散、抢拍的切点**，v4.6 换成了**连续的镜头内运动** —— 运动量够，但连续运动不带拍点，脉搏就没了；
  ③ 早期有一条**加速曲线**（静 → 闪帧串 → 每拍切 → drop 密切），v4.6 前 51 s 平、drop 只到一半密度，对比弱。
- **05 的 drop 密度是原片脚手架「白送」的**：3.2 s 的原片段落里自带 2–3 个切，1.25× 又把它压密、把镜头内动作加快。v4.6 把脚手架换成自己的单镜头（一段一个连续镜头），密度就得**自己设计**，不能指望素材带。
- **「先快后缓」的插入镜头是 drop 里静止的来源**：缓的尾巴留得太长（0.8 s 以上），在最响的段落里读成等待。
- 开头的静不是问题：05 的开头比 v4.6 还静，👤喜欢。「讨厌干等」针对的是**音乐满的时候画面静**。
- threat 相关 ≈ 0 说明这个通道不是早期版本好的原因，别拿它当剪辑目标。

## 4. 下一轮重剪的规则（可执行）

0. **先修 `edl.py preview` 的欠帧再重出**，出片后检查：视频时长 = 剪辑表 end，任意一个闪帧的位置和剪辑表差 ≤1 帧。
1. **切点抢拍 1–2 帧**：切在拍前 0.04–0.08 s（按当前 `感官.json`），不要切在拍后。
2. **密度曲线**（切点 + 闪帧，按小节算）：intro ≤0.3｜回想 ≈1.4｜build ≈2，最后 2 小节每拍一切｜drop1 / 狂语 ≥2。
3. **drop1 骨架**：每个重拍（1.6 s）一个硬切 + 每小节 1 个拍上的内部强调（1 拍短插入 / 2–3 帧闪 / 素材自带的切），让 ≥1/3 的镜头 ≤1 拍、镜头中位 ≈0.7 s。乐句边界给最大的变化。
4. **音乐满的段落里，镜头内运动 < 1 不超过 1.5 s**（05 的上限是 1.8 s）；「先快后缓」的插入镜头，缓的尾巴 ≤ 半小节（0.8 s）就切走。
5. **回想 / build 保留 v4.6 的运镜，但把闪帧串加回来**：每个乐句边界一串 3–7 个闪帧的抖动（v2 在 16.3–17.1 s、29.1–29.9 s），不只是单个 blink；单镜头不超过 1 个乐句（6.4 s）—— v4.6 的回想有一个 12.8 s 的镜头。
6. **脚手架**：还没有自己画面的地方，学 05 用 2 小节一段的原片 @1.25×（自带内部切），别用单个 1.6 s 镜头；换成自己画面时，每段要自带 1–2 个内部事件（变速冲击、闪、景别跳）。

## 5. 没做到 / 没验到的

- **检测器只在 v4.6 上有完整真值**：对剪辑表 40 个切点检出 39 个（漏 63.42 s，一个很暗的原片接原片），多出的 1 个（84.25 s）是 11c 片段里本来就设计好的「84.909 诡异声独立镜头」（漂移后）。05 只校了剪辑表的 15 个 drop 切点（15/15），原片内部的切和 v2 里的特效闪烁**没有真值**，可能把特效里的强闪也算成了切。
- 「静止」阈值（帧差 < 1，160×90 灰度）是我定的，同时看了 < 2 的结果，结论方向不变；但它测的是像素变化，暗画面里的慢动作可能被低估。
- 没有逐段看完整视频，只抽了 26–32 s（v2）、57–62 s（v4.6 / 05）、67–71 s、92–96 s 的接触表。
- 「抢拍 1–3 帧」部分可能来自 2026-10-21 `感官.json` 整体后移 0.04 s 之前用旧拍点剪的；规则 1 取的是保守值。
- 所有「为什么」都是推断，没有让 👤 做 A/B 盲看验证。
